What is on your Mac that your dotfiles don't know about?

Dredge scans your home directory, compares it with your stow or chezmoi repo, and tells you which untracked files hold secrets. It only reads. It never prints a secret value.

One scan, four answers

The report is built in layers, from the most dangerous at the top to the most routine at the bottom. Every row is a path, a rule name and a line number.

Committed secrets
Secrets already sitting in your dotfiles repo, found without git. Dredge reads your .gitignore files itself and skips what git would skip, so it does not cry wolf about files that were never committed.
Untracked secrets
Private keys, GitHub tokens, AWS access keys and ngrok tokens in files your repo does not manage. These are the ones you must not commit by accident.
Untracked config
Config for 58 known apps that your dotfiles repo has no copy of. Unknown folders are listed separately, with the risky ones first.
Tracked, drifted
Files your repo does manage whose content on this machine no longer matches the repo copy, compared by SHA-256.

Built so it cannot leak what it finds

A tool that hunts for secrets is the last thing that should carry one. Dredge's guarantees are structural, not promises.

  • No value field. A finding holds a rule name, a path and a line number. There is nowhere to put the secret, so it cannot reach the terminal, the JSON or a log.
  • Read only. It never writes, moves or deletes anything in your home directory or your repo.
  • Symlinks are never followed. Every file is checked with lstat and opened without following links, so a link cannot point it at something else.
  • Pipes and devices are never opened. A FIFO or a device named .gitignore cannot hang the scan.
  • Every read is bounded. Files over 1 MiB are not scanned for secrets, and the walk stops at depth 6.

Works with the layout you already have

Point it at one or more dotfiles directories. It detects stow or chezmoi on its own, and it works with neither.

  • Repeat --dotfiles to track several stow directories at once. The first one listed wins when two define the same file.
  • List paths you chose not to track in a .dredgeignore file. Ignored paths leave the untracked list, but secrets and drift are always reported.
  • Add --watch <path> to force a secret scan of a path the normal walk skips, such as a folder inside an app's cache.
# one stow repo
dredge scan --dotfiles ~/dotfiles

# two stow repos, plus one extra folder
dredge scan \
  --dotfiles ~/dotfiles-common \
  --dotfiles ~/dotfiles-work \
  --watch ~/.config/env

# machine readable, for scripts
dredge scan --json
# use it in CI or a pre-push hook
dredge scan --fail-on secrets,drift

# exit 0  nothing to fix
# exit 1  a condition in --fail-on was met
# exit 2  dredge itself failed

Take a core sample of your machine

Dredge is a single Rust binary. It is not on crates.io yet, so install it from the repository. You need Rust 1.88 or newer.

cargo install --git https://github.com/dterana/dredge
dredge scan --dotfiles ~/dotfiles

Your first run lists every untracked item. Copy the paths you do not want to track into a .dredgeignore file, and the next run shows only what is new.
